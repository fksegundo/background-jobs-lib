# Data model

> [Versão em português](data-model.pt-BR.md)

All state lives in Postgres under the `background_jobs` schema — three tables,
one sequence, one advisory-lock key. Migrations are embedded SQL resources
(`src/BackgroundJobs/Migrations/*.sql`) applied in filename order at engine
startup; `_migrations` records applied versions.

## `background_jobs.jobs`

One row per job. `id` is a uuid generated by the library and exposed as an
opaque string.

| Column | Type | Notes |
|---|---|---|
| `id` | uuid PK | opaque id returned by `EnqueueAsync` |
| `name` | text | stable handler identifier registered by the app |
| `args` | jsonb | serialized handler arguments |
| `state` | text | `scheduled`,`enqueued`,`processing`,`succeeded`,`failed`,`deleted` (CHECK) |
| `attempts` | int | attempts **started** since create/last requeue; incremented inside the claim tx |
| `max_attempts` | int | 1..10 (CHECK) |
| `retry_delay_ms` | int | 0..60000 (CHECK) |
| `generation` | int | bumped by requeue; scopes attempt numbering |
| `scheduled_at` | timestamptz | eligibility instant; `NULL` outside `scheduled` |
| `enqueued_at` | timestamptz | queue-entry timestamp for the current enqueued period |
| `enqueue_seq` | bigint | monotonic tiebreaker from `enqueue_seq` sequence |
| `created_at`/`updated_at` | timestamptz | Postgres `clock_timestamp()` |

Constraints:

```sql
CHECK (attempts <= max_attempts)
CHECK ((state = 'scheduled') = (scheduled_at IS NOT NULL))
```

Indexes:

```sql
jobs_enqueued_order  ON (enqueued_at, enqueue_seq, id) WHERE state='enqueued'
jobs_scheduled_due   ON (scheduled_at, id)             WHERE state='scheduled'
jobs_processing      ON (id)                           WHERE state='processing'
```

All hot reads hit partial indexes only — finished jobs never pollute the
queue index.

## `background_jobs.attempts`

One row per attempt that **started**. An attempt row is inserted inside the
claim transaction — it exists before the handler is invoked.

| Column | Type | Notes |
|---|---|---|
| `id` | bigint identity PK | also the chronological order key per job |
| `job_id` | uuid FK → jobs | |
| `generation` | int | job's generation at claim time |
| `attempt` | int | 1-based within the generation |
| `claim_token` | uuid | unique per claim; resolves ambiguous commits |
| `started_at` | timestamptz | set by `clock_timestamp()` in the claim tx |
| `finished_at` | timestamptz | NULL while running; detection time for `interrupted` |
| `outcome` | text | NULL while running; else `succeeded`,`failed`,`interrupted` |
| `error` | text | NULL unless the attempt failed/interrupted |

Constraints:

```sql
UNIQUE (job_id, generation, attempt)
CHECK ((outcome IS NULL) = (finished_at IS NULL))
-- one open attempt per job:
CREATE UNIQUE INDEX attempts_one_open ON attempts (job_id) WHERE outcome IS NULL;
```

`attempts_one_open` is the DB-level guarantee behind "a job never runs in two
workers": a second claim can't even commit.

Attempt outcome semantics:

| outcome | written by | meaning |
|---|---|---|
| `succeeded` | completing worker | handler returned without error |
| `failed` | completing worker | handler threw; `error` = exception message |
| `interrupted` | startup recovery | process died mid-attempt; `finished_at` is the detection time (true death time is unknowable) |

## `background_jobs.history`

Append-only audit of state transitions — including creation.

| Column | Type | Notes |
|---|---|---|
| `id` | bigint identity PK | chronological order within a job |
| `job_id` | uuid FK → jobs | |
| `state` | text | the state **entered** |
| `at` | timestamptz | Postgres `clock_timestamp()` |
| `reason` | text | fixed english reason strings |

Ordering is by `id`, not `at` — two transitions can share a timestamp
resolution, `id` can't.

Reasons emitted by the implementation: `created (immediate)`,
`created (scheduled)`, `became eligible`, `claimed by worker`,
`attempt succeeded`, `retry scheduled`, `attempts exhausted`,
`recovered interrupted attempt`, `interrupted attempt exhausted limit`,
`manually deleted`, `manually requeued`.

## Sequence

`background_jobs.enqueue_seq` — assigned on every transition into `enqueued`
(create-immediate, promotion, recovery, requeue). Combined with `enqueued_at`
it defines the FIFO order for the single-worker case.

## Advisory lock

`pg_advisory_lock` key `0x62676A6F62733031` ("bgjobs01") on a dedicated
unpooled connection. Held for the whole engine lifetime; released explicitly
on clean shutdown and by Postgres itself on connection death. A second
executor process fails at startup instead of competing.

## Notification channel

`bgjobs_wakeup` (configurable via `BackgroundJobsOptions.NotifyChannel`).
Payload carries no data — `'wakeup'` is enough; listeners always re-read the
tables. `pg_notify` is issued inside mutating transactions, so it fires only
after commit.

## Lifecycle example

`fail-n-times{failTimes:2}`, `maxAttempts=3`, `retryDelayMs=500`:

```
jobs.state:   enqueued → processing → scheduled → enqueued → processing
              → scheduled → enqueued → processing → succeeded

attempts:  #1 failed (error='demo failure')
           #2 failed (error='demo failure')
           #3 succeeded

history:   created (immediate) / claimed by worker / retry scheduled /
           became eligible / claimed by worker / retry scheduled /
           became eligible / claimed by worker / attempt succeeded
```

Kill -9 during attempt #3 instead:

```
attempts:  #1 failed, #2 failed, #3 interrupted   (finished_at = detection)
next start: attempts(3) == max_attempts(3) → jobs.state=failed,
            history += interrupted attempt exhausted limit
```
